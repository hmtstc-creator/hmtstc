# API Contract Inventory

## 1. Amac

Bu dokuman mevcut backend route yuzeyini kod degistirmeden tek bir contract envanteri olarak ozetler. Paket 2 API davranisi, auth davranisi, Binance logic veya real-trade logic degistirmez.

## 2. Backend Entry Point

Backend entrypoint:

```text
backend/main.py
```

`backend/main.py` FastAPI app'i olusturur, CORS'u ayarlar, test flagleri yoksa runtime scheduler'i baslatir ve route modullerini include eder.

App-level endpoints:

| Endpoint | Method | Auth | Purpose |
| --- | --- | --- | --- |
| `/` | GET | Public | Service metadata |
| `/health` | GET | Public | Basic health payload |
| `/health/ops` | GET | Public | Runtime/deploy operational health |

## 4. Auth Shape

Auth gates live in `backend/core/auth.py`:

```text
require_user
require_owner
require_admin
```

Most endpoints require bearer auth. Owner-heavy surfaces include users, production, real trade, some audit exports/deletes and Binance account/order controls.

## 6. Owner/Admin Endpoints

Owner/admin-risk surfaces:

- `/api/users*`: user creation, activation, password reset, package/API connection actions.
- `/api/real*`: real-trade health, lock/unlock, previews, dry-runs, order placement, pilot and emergency controls.
- `/api/production*`: production readiness and operational checks.
- `/api/binance/account-check` and `/api/binance/test-market-buy`: Binance account/order-adjacent controls.
- `/api/futures/admin*`: Futures permission/admin controls.
- `/api/audit/export` and audit delete.

## 7. Binance / Futures / Real Trade Risk Surface

The repo includes Binance-facing and real-trade-facing route/service modules. Paket 2 makes no behavior changes to:

```text
backend/routes/binance_routes.py
backend/routes/binance_futures_routes.py
backend/routes/real_routes.py
backend/services/binance_*.py
backend/services/real_*.py
frontend/js/app/realTrade.js
frontend/js/app/realApproval.js
```

Credential hygiene is handled at repository policy level only.

## 8. Paket 2 Karari

Paket 2 locks the API contract as documented inventory. Any endpoint add/remove/rename after this package should update this file or regenerate an equivalent inventory.

## 8.1 Paket 3 Contract Guard Karari

Paket 3 ile API contract guard tekrar uretilebilir hale getirildi. `40.08 --strict` sonucu `status=ok`, `missing_path_count=0`, `method_mismatch_count=0` olarak uretilmektedir. Runtime store policy ihlalleri tracked/unignored temeline gore degerlendirilir; ignored ve untracked local runtime store varligi tek basina hata degildir.
